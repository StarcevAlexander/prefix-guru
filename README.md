# prefix-guru

**Autoprefixer for Rust** — adds and removes `-webkit-`, `-moz-`, `-ms-` and `-o-` prefixes in CSS for the browsers you target, ports the warning texts, control comments, cascade formatting and value rewrites of Autoprefixer, and ships its own browserslist engine. Zero runtime dependencies beyond [postcss-guru](https://crates.io/crates/postcss-guru).

The port follows Autoprefixer 10.4.24 line by line — the processor, the 60 declaration hacks, the value and selector hacks, at-rules, `@supports`, transitions and the resolution media query — and every layer is checked against the real thing: the test suite replays fixtures generated by Autoprefixer itself and every output stylesheet, warning text, warning position and error must match.

For CSS processors, build tools and style pipelines in Rust that need the same output Autoprefixer would produce.

## Install

```toml
[dependencies]
prefix-guru = "0.1"
```

The crate depends on `postcss-guru` and `regex`. `serde_json` is used only by the tests.

## Quick start

```rust
use prefix_guru::{Autoprefixer, Options};

let prefixer = Autoprefixer::new(Options::default())?;

let output = prefixer.process("a { user-select: none; transition: transform 1s }")?;

assert_eq!(
    output.css,
    "a { -webkit-user-select: none; -moz-user-select: none; user-select: none; transition: transform 1s }"
);
```

`process` returns an `Output` with the finished `css`, the `messages` (warnings in Autoprefixer's format, with file, line and column) and the parsed `tree` for further editing.

### As a plugin

`Autoprefixer` implements `postcss_guru::Plugin`, so it runs in the shared pipeline:

```rust
use postcss_guru::process;
use prefix_guru::{Autoprefixer, Options};

let prefixer = Autoprefixer::new(Options {
    browsers: Some(vec![
        "ie 10".into(),
        "ie 11".into(),
        "safari 5.1".into(),
        "android 4".into(),
    ]),
    ..Options::default()
})?;

let output = process("::placeholder { color: red }", &[Box::new(prefixer)])?;
assert_eq!(
    output.css,
    "::-webkit-input-placeholder { color: red }\n:-ms-input-placeholder { color: red }\n::placeholder { color: red }"
);
```

## Browsers

By default the targets are the browserslist defaults (`> 0.5%`, `last 2 versions`, `Firefox ESR`, `not dead`):

```rust
use prefix_guru::{Autoprefixer, Options};

let prefixer = Autoprefixer::new(Options { browsers: Some(vec![
    "chrome 40".into(),
    "safari 8".into(),
    "ie 11".into(),
]), ..Options::default() })?;

assert_eq!(prefixer.browsers(), &["chrome 40".to_string(), "ie 11".to_string(), "safari 8".to_string()]);
```

The built-in engine ports the core of browserslist 4.28: explicit versions and ranges, `last N versions`, `last N major versions` (globally or per browser), `unreleased versions`, `since YYYY`, `>`, `>=`, `<`, `<=` usage shares, `cover`, `dead`, `Firefox ESR`, `OperaMini all`, `PhantomJS`, browser aliases (`ff`, `ios`, `explorer`, …), `defaults` and `not` with `and`/`or` composition. Queries it does not support (`electron`, `node`, `baseline`, `supports`, custom stats and config lookups) return a `QueryError` naming the query instead of silently widening the selection.

`defaults()` resolves the default query set, and `browserslist(&["last 1 version"])` runs the engine directly.

## Options

| Option     | Default      | Meaning                                                                 |
| ---------- | ------------ | ----------------------------------------------------------------------- |
| `browsers` | `None`       | browserslist queries; `None` means the defaults, `Some(vec![])` selects nothing |
| `add`      | `true`       | add missing prefixes                                                     |
| `remove`   | `true`       | drop prefixes that are no longer needed                                  |
| `cascade`  | `true`       | align prefixed declarations in a visual cascade                          |
| `flexbox`  | `Flexbox::All` | `No2009` skips the 2009 spec, `None` disables flexbox prefixes entirely |
| `supports` | `true`       | prefix inside `@supports` conditions                                     |

## Control comments

```css
/* autoprefixer: off */
a { user-select: none }

/* autoprefixer: ignore next */
b { transition: transform 1s }
```

`autoprefixer: off` and `autoprefixer: on` apply to the whole block, a second control comment in one block produces the same warning as the original, and `ignore next` disables only the following declaration or rule.

## Warnings

Outdated syntax reports the same texts and positions as Autoprefixer:

```rust
let output = prefixer.process("a { background: linear-gradient(left, white, black) }")?;

assert_eq!(
    output.messages[0].text,
    "Gradient has outdated direction syntax. New syntax is like `to left` instead of `right`."
);
```

When the target browsers need no prefixes at all, the time-capsule warning of the original is emitted too.

## Grid

Autoprefixer's Internet Explorer Grid translation (`grid-template-areas` autoplacing, `grid: true` and `autoplace`) is not implemented. The `/* autoprefixer grid: on */` control comment or the `AUTOPREFIXER_GRID` environment variable makes `process` fail with a `GridError` instead of silently producing different output; through the `Plugin` trait, where a run cannot fail, the same condition becomes a warning and the processing is skipped. Grid declarations are still recognised and left untouched, exactly like Autoprefixer with `grid: false`.

## What is verified

| Layer          | Fixture                                              | Compared                                        |
| -------------- | ---------------------------------------------------- | ----------------------------------------------- |
| Processing     | 78 hand-written styles × 12 browser and option sets  | output stylesheet after every run               |
| Warnings       | every warning above                                  | text, line, column, end line, end column        |
| Browserslist   | 152 queries against browserslist 4.28                | selected browsers and every error text          |
| Value parsing  | 94 values against postcss-value-parser 4.2           | full token dump and re-stringified value        |

The fixtures are generated by running Autoprefixer 10.4.24, browserslist 4.28.1 and postcss-value-parser 4.2.0 on the inputs and recording what they return; the tests replay the inputs and require identical results. The same harness was run during development on six real-world stylesheets (Bootstrap, AG Grid, ngx-bootstrap) across all twelve browser and option sets without a single difference.

## Differences from Autoprefixer

- **No IE Grid translation.** The ~855-line `grid-template-areas` autoplacement engine is out of scope; see *Grid* above.
- **browserslist subset.** Configuration files, `package.json` lookups, environments, custom stats, `electron`, `node`, `baseline` and `supports` queries are not supported; the supported core is listed under *Browsers*.
- **No source maps, `info()` report or PostCSS option plumbing.** The crate processes CSS strings and `postcss_guru::Tree`s.
- **Lone surrogates.** JavaScript strings can hold half of a surrogate pair; Rust strings cannot. Where the original cuts an emoji in half, this crate keeps the whole character.
